# Vercel & Railway Deployment Checklist — Social Pro

Use this checklist to ensure a smooth production deployment.

## Pre-Deployment (Setup Phase)

### GitHub Repository
- [ ] Repository is public or accessible to Vercel/Railway
- [ ] All changes committed and pushed to main branch
- [ ] No uncommitted changes locally
- [ ] GitHub Personal Access Token created (for CLI tools if needed)

### Frontend (Vercel)
- [ ] `vercel.json` exists at repo root
- [ ] `apps/web/next.config.ts` has `output: "standalone"`
- [ ] No hardcoded localhost URLs in frontend code
- [ ] All TypeScript types correct (`pnpm typecheck` passes)
- [ ] Build succeeds locally: `pnpm turbo build --filter=web`

### Backend (Railway/Render/Fly.io)
- [ ] NestJS API builds successfully: `pnpm turbo build --filter=api`
- [ ] No hardcoded localhost values in env config
- [ ] `apps/api/src/main.ts` uses `process.env.CORS_ORIGIN` for CORS
- [ ] All environment variables documented in `.env.example`
- [ ] Database migrations are idempotent (can run multiple times safely)

### Database & Services
- [ ] Prisma schema up to date: `npx prisma generate`
- [ ] Database migrations are tested locally
- [ ] Seed data (if any) is non-destructive
- [ ] Redis configuration tested locally

- [ ] `SMTP_*` variables set (email provider details)

- [ ] `ANTHROPIC_API_KEY` set (if using Claude for AI)
- [ ] `OPENAI_API_KEY` set (if using OpenAI)

- [ ] All OAuth `*_CALLBACK_URL` updated to Railway domain

## Troubleshooting

### Frontend Deployment Issues

**Build fails with "pnpm not found"**
- Vercel install command must be `pnpm install`
- Check `vercel.json` `installCommand` setting

**Build succeeds but site shows 404**
- Check `outputDirectory` is `apps/web/.next`
- Check `rootDirectory` is `apps/web`
- Rebuild deployment

**NEXT_PUBLIC_API_URL is undefined**
- Environment variables not set in Vercel
- Missing `NEXT_PUBLIC_` prefix
- Redeploy after setting variables

**API calls failing with CORS error**
- Check backend `CORS_ORIGIN` allows Vercel domain
- Verify backend is running and reachable
- Clear browser cache and reload

### Backend Deployment Issues

**Build fails with missing Prisma**
- Add `postinstall` script: `prisma generate`
- Or ensure build command includes dependency generation
- Rebuild

**Database connection fails**
- Verify `DATABASE_URL` is set
- Check PostgreSQL service is running
- Restart service in Railway

**Migration fails**
- Connect to Railway shell and check migration status
- Fix migration issues locally first
- Rerun migration in production

**CORS errors from frontend**
- Update `CORS_ORIGIN` env var to match frontend domain
- Redeploy backend
- Verify change in logs

## Rollback Procedure

### Frontend Rollback (Vercel)
1. Vercel Dashboard → **Deployments**
2. Find previous successful deployment
3. Click **...** → **Promote to Production**
4. Confirm rollback

### Backend Rollback (Railway)
1. Railway Dashboard → **Deployments**
2. Find previous successful deployment
3. Click **...** → **Redeploy**
4. Confirm rollback

## Performance Baseline

After deployment, establish performance baselines:

### Frontend (Vercel)
- [ ] First Contentful Paint (FCP) under 2 seconds
- [ ] Largest Contentful Paint (LCP) under 4 seconds
- [ ] Cumulative Layout Shift (CLS) under 0.1
- [ ] Total page size under 1 MB (JS + CSS + assets)

### Backend (Railway)
- [ ] API response time under 500ms (p50)
- [ ] API response time under 1s (p95)
- [ ] Database query time under 100ms
- [ ] Error rate under 1%

Monitor these in:
- Vercel Analytics dashboard
- Railway metrics tab
- Browser DevTools Performance tab
